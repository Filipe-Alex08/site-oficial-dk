## graphify (codebase knowledge graph)

`graphify-out/` holds a knowledge graph of this repo (`graph.json`, `GRAPH_REPORT.md`, `graph.html`).

For any question about architecture, file relationships, "where is X", "what depends on X" or "how does X work":

1. If `graphify-out/GRAPH_REPORT.md` exists, read it first (god nodes, communities) before using Grep/Glob over the codebase.
2. Then query the graph instead of scanning files blindly:
   - `graphify query "<question>"` for a BFS traversal (add `--budget N` for more output)
   - `graphify explain "<node>"` for a node and its neighbors
   - `graphify path "<A>" "<B>"` for how two things connect
   - `graphify affected "<node>"` for what a change would impact
3. Use Read/Grep afterwards to confirm details in the actual files. The graph is a map, not the source of truth.

Keep it fresh: after meaningful code changes (new files, renamed or removed modules), run `graphify update .` (no LLM needed; add `--force` only after deleting code). If the graph looks older than the files in question, say so and update it before relying on it.

`/graphify` is still the entry point for a full rebuild.
